◆ Error

enum class canopen_client::Error : uint8_t
strong

Why a call failed. Values 0 to 9 are the shared base set; client-specific values start at 16.

DeviceIdMismatch, Crc and Busy are never returned: the CAN controller checks the frame CRC, and every call blocks until it finishes.

Enumerator
Ok 

The call succeeded.

NotInitialized 

EnsureInitialized() has not succeeded, or Deinitialize() ran since.

InvalidArgument 

An argument or a Config field is out of range; nothing was sent.

Bus 

The port failed to send or to receive a frame.

Timeout 

No valid reply arrived in time (SDO, node guarding, drive state).

DeviceIdMismatch 

Not returned by this driver.

Crc 

Not returned by this driver.

Busy 

Not returned by this driver.

DeviceFault 

A read-back showed a value other than the one written.

Unsupported 

The call needs a port hook the port lacks, or a transfer type the driver does not implement.

SdoAbort 

The node aborted the SDO transfer; see GetLastAbort().

Protocol 

A reply broke the protocol (command specifier, toggle bit, size).

BufferTooSmall 

An upload is larger than the caller's buffer.

InvalidFrame 

A frame fails validation (identifier, length or content).

NodeState 

The node is known to be in an NMT state that ignores the request.

DriveFault 

The drive is in the Fault state or reports a state no transition leaves.

◆ kMaxReceivesPerWait

constexpr uint32_t canopen_client::kMaxReceivesPerWait = 65536
inlineconstexpr

Receive() calls one blocking wait makes at most, whatever they return, before it gives up. Only frames count against kMaxFramesPerWait; this bounds a port that returns early with no frame.
