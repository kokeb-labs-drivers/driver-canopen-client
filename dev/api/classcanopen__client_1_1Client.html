Detailed Description

template<CanPort Port>
class canopen_client::Client< Port >

A CANopen client on one CAN bus.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one way to start, use, optionally Deinitialize(). Every call that touches the bus returns Error::NotInitialized until EnsureInitialized() has succeeded; no call starts it as a side effect.

Two kinds of port. A CanPort (hooks EnsureInitialized and Send) gives the transmit-only mode: SendNmt(), SendSync(), SendRpdo() and SdoDownloadUnconfirmed(). A CanRxPort adds Receive and NowUs and gives everything else; the calls that need a reply are constrained on it and do not exist on a transmit-only port.

One request is in flight at a time. The class is not thread-safe: call it from one task, or serialise the calls.

Optional hook: void Log(LogLevel, const char* message) noexcept.

template<CanPort Port>

noexcept

Start the client, once: the only way to initialise the driver.

The first call checks the configuration, starts the port and clears the node table, the PDO subscriptions, the EMCY queue and the counters. After it succeeds, later calls return Ok at once with no I/O. After it fails, the driver stays uninitialised.

Returns
Ok, InvalidArgument (the stored configuration fails Validate(); the port is not touched) or Bus (the port could not start).

Diagnostic: send one frame exactly as given. A single Send(): no retry, no routing, and none of the driver's state (node table, toggle bits, node states) is touched. It bypasses the safety and state guards: any frame goes out, an NMT command or a controlword included, and the node table does not learn of it.
