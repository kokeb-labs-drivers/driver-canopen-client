CAN transceiver

CANOPEN_CLIENT Driver¶

A generic C++20 CANopen client over a classic CAN frame port: NMT master, SDO client, heartbeat, emergency, SYNC, PDOs and a CiA 402 drive state machine.

Quickstart API guide Source on GitHub

The SN65HVD230 is a 3.3 V CAN transceiver, the reference physical layer of a CANopen node: it turns a CAN controller's TXD and RXD into the differential CANH and CANL signals of an ISO 11898-2 bus, and this driver speaks CANopen to the nodes on that bus (1 Features, 2 Applications, 3 Description, p. 1).

Where it is used¶

  • Industrial automation, control, sensors and drive systems
  • Motor and robotic control
  • Building and climate control (HVAC)
  • Telecom and basestation control and status
  • CAN bus standards such as CANopen, DeviceNet and CAN Kingdom

Uses named by the datasheet (1 Features, 2 Applications, 3 Description, p. 1).

Quick start¶

Wire the node as above, write the port (Porting), then read a node's device type and start it:

#include "canopen_client.hpp"

int read_node_and_start_it(MyPort& port, uint32_t& device_type) {
  canopen_client::Client<MyPort> client(port); // no I/O yet

  if (auto r = client.EnsureInitialized(); !r) { // 1. CAN controller up
    return static_cast<int>(r.error);            //    Bus: the port could not start it
  }
  const auto type = client.ReadDeviceType(5); //    2. SDO read of object 0x1000 from node 5
  if (!type) {
    return static_cast<int>(type.error); //    Timeout: nobody answered; SdoAbort: the node refused
  }
  device_type = type.value;
  if (auto r = client.SendNmt(canopen_client::NmtCommand::Start, 5);
      !r) { // 3. node 5 to Operational
    return static_cast<int>(r.error);
  }
  return 0;
}

From docs/hardware.yml; kokeb-docs hardware --check confirms that every API name is in inc/canopen_client.hpp, inc/canopen_client_types.hpp and every object in inc/canopen_client_types.hpp, inc/canopen_client_protocol.hpp and every named test exists.

The driver is not tied to a product or to a CAN controller. You give it a small class that sends one 11-bit frame, waits for one and reads a microsecond clock; it does the rest: the SDO transfer rules, heartbeat ageing, the emergency queue, PDO configuration in the order the profile prescribes and the drive's state transitions.

  • One object per bus, no I/O until EnsureInitialized(). See API guide.
  • Errors you can act on: Result<T> with an Error, and the node's own SDO abort code. See Contract.
  • Zero-overhead portability: a CRTP port checked by a concept; a send-only port gets a send-only API. See Porting.
  • Tested without hardware against an independent model of the bus and its nodes. See Testing and CI.
